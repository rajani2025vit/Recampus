    OS concepts demonstrated

    Each card says which concept is shown, how ReCampus implements it, and what you can observe while testing.

    A

    Non-preemptive Priority Scheduling with FCFS

    Concept

    A CPU-scheduling policy: the dispatcher always picks the ready process with the highest priority. Processes with equal priority run First Come, First Served. Non-preemptive means a running process is never interrupted.

    In ReCampus

    Each Lost report is a process: its report id is the PID, High/Low is its priority and the submission order is its arrival order. Process Next Report picks High before Low, and the lowest PID among equals. A new High report must wait until the running one is completed.

    Try it

    Submit Low, Low, High on the Lost page. The High report is first in the queue above. Start it, then submit another High: it moves to the top of the queue but does not interrupt the running report.

    B

    Process state management

    Concept

    A process moves through states during its life. A simple model uses Ready, Running and Terminated.

    In ReCampus

    OS stateReport state
    ReadyPending
    RunningProcessing
    TerminatedCompleted

    Every change is stored in the database and written to the state-change log.

    Try it

    Watch the coloured counts in the diagram and the badge on each Lost card change after every button press. This model has no “waiting/blocked” state.

    C

    Mutual exclusion and concurrency control

    Concept

    Only one process may be inside a critical section at a time, so two actors cannot both claim the same exclusive thing.

    In ReCampus

    Only one report may be Processing. Starting a report runs as one SQLite BEGIN IMMEDIATE transaction that takes the database write lock, checks “is anything Processing?” and then updates. A UNIQUE index lets the database itself reject a second Processing row. A Python lock alone would not be enough: it only protects one Python process, not the database.

    Try it

    Sign in as an administrator in two browser tabs and press Process Next Report in both: only one starts a report, the other shows the message “already Processing”.

    D

    Resource allocation (exclusive resources)

    Concept

    An exclusive resource can be held by one process at a time. It is allocated, used, then released so others can use it.

    In ReCampus

    A lend item is the resource. Approving a borrow request allocates it (Available → Borrowed); marking it returned releases it (Borrowed → Available). Both steps are atomic transactions, and a UNIQUE index allows only one Approved request per item.

    Try it

    Make two requests for one item. Approve the first, then try to approve the second: it is refused until the item is returned.
